# SQMC–EKF implementation audit

Reviewed working tree based on commit `6fd15592de4af4569dd9b6b373c93d63437b3aba`, including the existing launcher edits. No repository files were changed during this audit. No Colab session or full training experiment was launched.

The code uses actual SQMC and factorial EKF algorithms. However, the execution and reporting pipeline is not ready to support the README's comparison claim. The defects below describe observable behavior, not intent.

## Findings requiring correction

1. **P1 — The comparison subprocess defaults to CPU despite provisioning a GPU.**
   `scripts/run_sqmc_ekf_gpu.py:190` sets precision and plotting environment variables, but never sets `RBSQMC_PLATFORM`. Imported `rbsqmc/src/model/rbsqmc/model_rbsqmc.py:55` and `rbsqmc/src/model/rbsmc/model.py:21` explicitly set `jax_platforms` to `cpu` when that variable is absent. The GPU check occurs in the setup process; training runs in a new process. Reproduction confirmed `jax_platforms='cpu'` after comparison imports. Set the intended accelerator before importing model modules and assert the active array/backend device inside the actual comparison process. Recording available hardware is insufficient evidence of its use.

2. **P1 — SQMC forecasting and state reporting discard the trained friendly scale.**
   `rbsqmc/comparison/sqmc_ekf/scripts/train.py:72` supplies learned per-match scales during SQMC optimization. `rbsqmc/comparison/sqmc_ekf/scripts/predict.py:61` passes only `params['model']` to the sequential predictor, which filters the entire history with default scale 1. `rbsqmc/comparison/sqmc_ekf/run.py:313` repeats the omission for states/correlations. Thus even non-friendly World Cup forecasts use a differently filtered historical prefix. On a 44-match fixture with 24 friendlies, changing the friendly scale from 2 to 7 changed scaled SQMC logZ from -159.571209 to -159.549756, but SQMC forecast grids changed by exactly zero; EKF grids changed by up to 0.0119365. Thread identical scales through training, prefix filtering, forecast grids, and state reporting. Additionally, configurable `match_scale != 1` affects only SQMC training, contrary to the shared-scaling comment; either support it consistently or reject it.

3. **P1 — The successful launcher path always raises after downloading results.**
   `scripts/run_sqmc_ekf_local.py:323` calls `download('run')`, which sets the run download state to `complete`. The next `download('root')` call immediately fails the unconditional guard at line 223 with `Refusing to overwrite a complete download`. Reproduced directly without network access. Track root metadata and run-result downloads independently; refreshing root metadata must not change or reject a completed results download. Failure recovery also downloads only root metadata, so partial training artifacts are not recovered before shutdown.

4. **P1 — Production validation can mark empty outputs as complete.**
   The GPU worker invokes `scripts/sqmc_ekf_protocol.py:166`, not the stronger standalone validator. This function checks only that a handful of file paths exist; the supplied configuration is unused. It accepted empty JSON, CSV, Markdown, and PNG files in a reproduction. It does not verify predictions, epoch count, numeric finiteness, valid probabilities, matching fixtures, or recomputed metrics. Archive hashes verify byte integrity, not scientific correctness. Wire a content validator into production before setting `execution='complete'`, checking exactly the configured epochs and both methods' full prediction records. The standalone validator also only compares the two CSV row counts; two equally truncated histories pass.

5. **P2 — The EKF pre-World-Cup ranking already includes the first World Cup result.**
   `rbsqmc/src/model/ekf/model.py:143` returns synchronized states after each match, excluding the prior. `run.py:297` nevertheless indexes them using the prior-inclusive SQMC convention. In a 44-match reproduction, the EKF wrapper has 44 rather than 45 states. Its `pre_index=40` exactly matches the state after the first prediction match and differs from the preceding state by up to 0.704619. Prepend a correctly timestamped prior or use an explicit common state-index contract. This affects the ranking, not the tested one-step-ahead forecasts.

6. **P2 — Final correlation plots use residual covariance, not full posterior covariance.**
   `scripts/plots.py:140` passes the augmented Gamma trajectory to the shared correlation plotter. `rbsqmc/src/utils/graphic.py:323` reads only `gamma[-1]`. The RB filter zeros sampled teams' residual covariance rows after conditioning, so this matrix omits uncertainty/dependence across weighted particle means. The complete covariance is `Gamma ⊗ B + sum_n w_n (vec(x_n)-mu)(vec(x_n)-mu)^T`. `weighted_sqmc_moments` claims covariance handling but actually returns only means. Compute the full covariance and label the chosen attack, defence, or total-strength team correlation; alternatively label the existing graph strictly as residual conditional correlation.

7. **P2 — The default experiment differs from the README.**
   `config/config.json:5` sets 256 particles; the README specifies 512. Both are legitimate power-of-two Sobol counts, so this is a configuration mismatch rather than a QMC substitution. Resolve the discrepancy explicitly before a reported full run. The full profile otherwise requests 100 epochs, learning rate 0.05, seed 0 and 25 gradient replicas; reductions happen only through the explicit local `--smoke` path.

8. **P2 — Several required diagnostics are omitted or discarded.**
   `scripts/plots.py:80` produces only logZ curves, not gradient-norm curves. Line 117 defaults to plotting only the last seven predictions; line 133 explicitly omits both prior/final correlation heatmaps. No per-match test-logZ difference is written. Fitted raw/constrained parameters are returned in memory but never saved; `train.py:139` writes only summaries and the CSV keeps only epoch/logZ. Raw quadrature/grid mass is discarded during normalization, and the unused `evaluate.py:70` truncation helper always returns zero. A real test grid had raw mass 0.8251224, so normalization does not imply zero omitted probability mass. Preserve raw grid mass and trained parameters, and generate the README's requested diagnostics. These omissions are not repaired by a successful process exit.

9. **P2 — Colab does not enforce the declared dependency versions.**
   `scripts/run_sqmc_ekf_gpu.py:112` installs only missing modules by unversioned package name; it never uses `requirements-gpu.txt` or verifies the installed Cuthbert API version. Preserving the working JAX/CUDA installation is reasonable, but the code explicitly targets Cuthbert 0.0.14. Validate the compatible runtime and pin/verify the non-CUDA dependencies rather than assuming any importable version is suitable.

## What was verified

- **Real QMC:** the filter generates a fresh scrambled five-dimensional Sobol block per match, starting at index zero. The implementation uses LMS plus a digital shift and the tracked Joe–Kuo table; the bootstrap generates and verifies the derived direction-number file against SciPy.
- **Real Hilbert sorting:** four playing-team coordinates determine the Hilbert permutation; corresponding weights are reordered before inverse-CDF ancestor selection. Complete Sobol rows are sorted on the resampling coordinate, preserving the pairing with all four propagation coordinates. Propagation uses the Gaussian inverse CDF, not independent normal draws substituted for QMC.
- **Legitimate conventions:** endpoint clipping is an explicitly documented finite-precision quantile convention. The resampling stop-gradient correction preserves forward weights while supplying the intended gradient estimator. Initial identical particle means represent the RB prior together with its residual covariance; they are not evidence of skipping the prior.
- **Matched optimization:** both methods use Adam/cosine decay, the configured number of updates, and final-epoch parameters. SQMC gradients average the configured replicas sequentially. Training aborts on non-finite objective/gradient/score values; this loop does not replace failed scores with earlier values. Test logZ is computed from a continuous train-plus-test pass by subtracting its training prefix.
- **No current-score forecast leakage in the exercised case:** changing the first prediction result left that match's forecast unchanged for both methods.
- **EKF reference fidelity at fixed parameters:** comparison with local cuthberto-carlos revision f79147e yielded identical raw Gauss–Hermite grids, maximum filtered-mean difference 1.10e-8, and logZ difference approximately 1.43e-7 across 44 matches. The small discrepancy is consistent with the reference's added dynamics jitter versus exact zero-time propagation here; the README's claim of exactly one deviation is therefore too strong.

## Data-pipeline assessment

The comparison currently uses **one loader with two adapters**, not two independently filtered source datasets. `data_ekf.py` creates `MatchInputs` with per-team previous-appearance times and `FootballResults` with successive match times from the same frame. This distinction is appropriate: factorial EKF can lazily propagate individual teams, whereas correlated SQMC advances the joint state. OU transitions compose over elapsed time; this representation difference alone is not a reason to excuse mismatched observations or likelihood scales.

The complete local CSV produced 4,702 training matches, 305 test matches, and 104 prediction matches, all 104 being World Cup fixtures. Both adapters' scores aligned exactly. One high-score source row is explicitly recorded as excluded by the configured goal cutoff. The input SHA-256 was `4db1d359d1438a23918df4af217da09b72dd92bb638f2a393d49d91616c92ce3`.

The remaining scientific caveats should be stated accurately: EKF's logZ is a Gaussian observation approximation while SQMC uses the discrete likelihood estimator; factorial EKF still permits within-team attack–defence covariance. Fixed covariance jitter and score-probability floors are numerical approximations, not mathematically exact operations. The existing SQMC jitter is at least 1e-4 and can dominate zero-time process variance; it deserves a targeted singular/zero-time regression before claiming exact preservation of the statistical model.
